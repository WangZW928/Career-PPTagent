# 简洁商业风格：版式参考

这些是已验证的参考值，不是所有 PPT 的固定规格。用户的最新示范页和当次要求始终优先。

## 推荐故事线

1. 封面：汇报主题、汇报人、角色和日期。
2. 概况：角色背景与三条主要工作。
3. 项目经历：时间、项目及工作、承担角色。
4. 代表工作：系统位置、架构与效果、关键技术及工程结果。
5. 组织贡献：先行工作、难点解决、团队贡献。
6. 未来规划：近期阶段交付与长期技术方向。
7. 工作总结／致谢：归纳已有成果，不引入新内容。
8. 技术备份：公式、代码、实验口径和补充图像。

这是信息顺序而不是固定页数。新稿按内容合并或拆页，编号、交叉引用和页脚随实际页序更新。

## 文案对照

| 较泛的表述 | 更具体的摘要 |
| --- | --- |
| 多项项目经历，连接三类技术能力 | 项目经历：项目及承担职责 |
| 把工程经验转化为可搜索、可验证的过程 | 代表工作一 · 优化工具：架构设计与验证结果 |
| 用最小 demo 展示具体实现 | 技术备份一 · 平台适配：主体代码与执行路径 |
| 下一阶段，承担更完整的技术责任 | 未来规划：阶段交付与长期方向 |
| 全面总结，感谢聆听 | 工作总结：核心模块、平台适配与工具建设 |

示例中的名称只说明句式，不应自动填入新稿。标题里有明确对象、动作或结果即可，不要求都写成同一个句型。

## 页面模板

### 概况页

- 顶部一条“主要工作”浅底横栏，先概括三个以内的核心方向。
- 左侧约四分之一宽深蓝信息卡，集中放必要的角色与经历信息；白字，信息按组留间距。
- 右侧用 01／02／03 编号列三项主要工作。每项只有“深蓝短标题 + 一至两行具体交付”，不做三个厚重卡片。

### 项目经历页

- 顶部一条“技术方向”横栏，下面用竖向时间线组织经历。
- 三列分别为日期、项目及工作、承担角色。日期与项目标题共基线，职责或关键词放在项目标题下一行；角色右对齐。
- 项目标题深蓝加粗，工作内容近黑常规字重，圆点、竖线和角色使用深蓝／浅灰。

### 项目案例页

- 单行“代表工作编号 · 项目：本页摘要”，下面细分隔线。
- 上方短挑战栏，中部真实结果图与流程图，下方一条本人工作、已完成或交付说明。挑战和本人工作也可上下排列在图区下方，按图意选择。
- 标签加粗，说明正文常规字重。标签后直接交代具体问题，不写空泛背景。
- 双分支流程保持同级节点尺寸一致、左右对称；结果图和流程图不要互相挤压。

### 架构与效果页

- 系统介绍页用一条工作流说明组件位置，再用“设计难点／本人工作”两条横栏交代贡献。
- 架构页让主图占主体，旁边只留支撑图意的短句；层次、验证、反馈和经验记录要有明确去向。
- 效果页组合真实曲线、代表算例表与工程结果。标明统计对象，不把实验中的最佳候选改称最终交付结果。
- 比较调用次数或性能时，区分比较阶段、预算、基线和统计范围，不为追求整齐省略口径。

### 组织贡献页

- 三列分别讲“先行工作、独立解决难点、团队贡献”。列首用 01／02／03、短标题和细横线，下面列三至四条事实。
- 列底可用极浅蓝、灰、米色区分，不大面积使用高饱和色，也不添加阴影和装饰图标。
- 区分“首先提出”“独立开发”“交付／分享”，不要把同一成果换三种说法重复计数。

### 关键数据与技术备份页

- 数据页可采用左右双栏：栏标题说明统计对象，深蓝数字写“原值 → 新值”，下一行写变化比例与候选口径；后续段落再交代正确性、复用条件和基线策略。
- 页面底部用灰色小字写真正影响理解的边界。边界说明要短，不写成整页免责声明。
- 公式备份页让主公式与符号定义相邻，区分已有方法、改进部分和实现分工，明确验证状态与来源。
- 代码备份页让真实代码截图占主体，旁边或下方用编号解释执行路径；不要把代码改成伪代码来凑简洁。
- 图像过程页按时间或阶段横向排列真实帧，标清参数与阶段，再放对应曲线；保持原图比例和坐标信息。

### 未来规划页

- 近期阶段可用逐级抬升的阶梯卡片，卡片深蓝顶条、圆角浅框；时间加粗，阶段标题深蓝，任务说明常规字重。
- 长期方向落在底部浅色圆角横条：左端短标签，中间两个方向分栏，细线分隔。
- 阶段与长期是承接关系：阶梯讲近期交付节奏，横条讲方向预研，不在卡片里混写长期内容。
- 外部案例或预测只作为方向依据，用少量编号引用放在空白区域；不抢占本人规划的主体位置。

### 工作总结与致谢页

- 可使用淡蓝到白纵向渐变，顶部 `#DEEBF7`、底部 `#FFFFFF`，保留统一标题和页脚。
- 主体只留三条横向总结：左侧深蓝加粗工作方向，右侧近黑常规字重交付结果；行距大，不加图标和卡片。
- 底部细线之上，左侧放汇报身份或申请目标，右侧放简短致谢。

## 16:9 模板尺度

参考画布为 1280×720，实际 PPT 页面为 960×540 pt。代码里的像素坐标和 PowerPoint 的字号 pt 不要混用。

| 元素 | 参考值 |
| --- | --- |
| 正文左右边距 | 约 56 px |
| 标题 | x=56，y≈30，宽约 1020 px，高约 45 px；24 pt |
| 标题下横线 | y≈84 px |
| 挑战／说明横栏 | 通常 y≈110–140 px，高约 48 px，按内容避让 |
| 普通正文、节点主标签 | 16.5 pt |
| 辅助标注、刻度、页脚 | 10.5 pt；不能为塞内容继续缩小 |
| 时间线纵向节距 | 约 100 px；日期、项目、角色共基线 |
| 多行能力表 | 行框约 78 px 高，框间约 34 px；内容两行时检查行内间距 |
| 页脚线与页码 | 约 y=676、684 px，留出必要空白 |

局部数字通常用粗体而非额外大字号；关键数据备份页的“原值 → 新值”可以使用局部大字号。封面不必使用正文三档尺寸。已有原图中的字形不能靠声明字体修改，必须检查实际渲染。

## 文件与编辑边界

- 按用户明确指定的文件和保存内容确认底稿，单看文件名版本号不够。处理前留存源文件，结束时检查修改时间或哈希，避免遗漏并行修改。
- 用户指定的个人目录只属于当前任务，不写成公共 skill 的默认路径，也不把真实个人文件打进开源仓库。
- 白底适用于正文，不覆盖合适的图片封面；淡蓝渐变只用于结尾总结页。
- 小字清理针对无信息量的编辑提示，不删除数据单位、统计口径和必要来源。
- 参考终稿中的个别手动换行、临时标记或局部拥挤不是必须复刻的风格；新稿仍需检查换行、遮挡、可读性和内容完整性。
- 本轮仅改字体／间距时，不顺带扩写规划、调整实验结论或增加页面。
