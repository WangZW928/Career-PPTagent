# 简洁商业汇报 PPT 风格

这套规则从已确认的演示终稿中抽象而来，只保留可复用的设计方法，不包含原始个人资料、组织标识或项目数据。目标是信息清楚、版面规整、证据可信，不追求宣传式包装。用户当次要求和最新手改稿优先于以下默认值。

## 叙事结构

- 技术汇报或答辩可采用“封面 → 概况 → 项目经历 → 代表工作 → 组织贡献 → 未来规划 → 总结 → 技术备份”。按内容增删，不机械凑页数。
- 主线回答“做了什么、由谁承担、难点在哪里、结果如何”；公式展开、主体代码、实验口径和补充曲线放入技术备份，主线不堆实现细节。
- 代表工作按项目组织。复杂项目可连续多页，分别讲系统位置、架构与效果、关键技术；不强迫一个项目只留一页。
- 页面标题可使用“代表工作一 · 项目：具体主题”“技术备份一 · 主题：补充证据”，编号与实际页序一致。

## 标题与文案

- 每页顶部使用**一行简短的标题摘要**，直接说明本页工作或结果；不拆成小栏目名、大口号、解释性副标题三层。
- 正文按实际需要交代“挑战、方案、本人工作、已完成／工作成果”。使用少量明确标签，不强迫每页凑齐这些栏目，也不让不同栏目重复同一句话。
- 直接写任务、动作、结果与贡献边界。少用“从……到……”“让……成为……”等泛化标题；只有确实说明技术关系时才保留。不为追求整齐添加空泛结论。
- 个人贡献用“负责、独立开发、主要参与、方案设计与实现”等准确口径；团队工作不笼统写成个人成果。
- 不把“评审修改稿”“缺项见备注”、材料编号、填写指令、“本页展示……”等制作提示放进演示正文。未提供的材料不补造成果；工作记录放在备注或项目文档。
- 对用户已认可的内容，只在请求范围内润色。保留专业术语、数字、贡献边界、确定程度与手动删改。中文定稿可配合 [Humanizer-zh](../humanizer-zh/SKILL.md) 复核，不默认重构全文。

## 字体、颜色与布局

- 中文默认 **Microsoft YaHei（微软雅黑）**；英文与数字默认 **Times New Roman**。图内标题、刻度和注释也应检查，不能只改正文文本框。平台缺少字体时使用项目支持的 CJK 回退字体，并检查导出效果。
- 每页尽量两到三个字号层级。16:9 模板参考：标题 **24 pt**，正文／节点主标签 **16.5 pt**，注释／刻度／页脚 **10.5 pt**。同级保持一致；通常用粗体而非额外字号区分主次，实际可读性优先于机械照搬数值。
- 正文页白底；标题和重点节点采用深蓝 `#1F4E79`，普通正文采用近黑 `#20252B`，辅助文字灰色 `#596579`，浅色底条 `#E9EFF5`，细边线 `#D7DEE5`。结尾总结页可用淡蓝到白纵向渐变（顶部 `#DEEBF7`、底部 `#FFFFFF`），但不推广到其他正文页。
- 封面可以使用一张与主题相关的高质量图片和简洁文字层级；不使用与内容无关的装饰插画。
- 保留统一的标题下细横线、底部细线和页码。如需品牌标识，使用用户提供的原模板资产；本风格不附带也不默认添加任何现实组织标识。
- 挑战、本人工作或成果适合放在简洁浅底横栏中：标签突出、正文常规字重；不把整条说明都加粗。
- 对齐优先：标题与正文左边缘一致，同级节点尺寸一致，分支对称。时间线的日期、项目名、角色共用同一行基线，增加行间空隙。
- 保留合适留白，不靠缩小整页字体塞入内容，也不为了填满空白增加装饰或重复文字。具体尺寸和页面模板见 [版式参考](references/style-reference.md)。

## 图文与技术材料

- 讲机制用流程图，讲成果用真实曲线、云图、运行图、表格或代码片段。“图文并茂”不等于每页都加插画。
- 流程图优先用可编辑的 PPT 原生形状、文字与连接线。深蓝重点节点、浅灰蓝普通节点，适量圆角、清楚箭头和对称分支即可。反馈图标明返回目标；不要为视觉闭环虚构步骤。
- 结果图与流程图可以同页并置，但加证据图时不要挤掉原有流程。原图按比例排版，保留色标、坐标、图例和比较对象。
- 关键数据页先让数字和变化关系可读，再补实验条件与边界。例如用深蓝“原值 → 新值”、短结论和底部灰色边界说明，不让限定条件淹没结果。
- 原始 GIF 完整嵌入 PPT，仅调整大小、位置和标签。静态预览不能冒称为最终 PPT 动画。
- 优先使用 LaTeX／数学排版生成公式并保留源码。公式备份页交代符号含义、贡献部分和验证状态；代码备份页保留真实代码，用少量步骤说明执行路径。
- 不编造缺失实验数据，不平滑或外推图片提取曲线。保留会改变结果理解的统计对象、比较基准、候选状态和适用范围。短限定留在图旁，详细条件和出处放备注或备份。
- 原始科学图的颜色和数据优先于装饰配色统一。字体若固化在图片里，不能声称设置文本框字体就已修改；不要为换字体生成近似的新曲线。

## 执行方式

1. **读取最新文件。** 使用用户最新指定或保存的版本，不默认仓库导出稿就是最新稿；处理前保留源文件，结束后核对修改时间或哈希。
2. **按范围修改。** 用户要求暂停或留待下一轮时不扩展修改；不能借字体或间距调整恢复用户删除的文字。
3. **保留可编辑性。** 通常配合 [PPTAgent](../pptagent/SKILL.md) 制作。现有手改 PPTX 可以局部原生编辑，避免从旧 HTML 全量重建覆盖用户修改。
4. **核对交付。** 渲染修改页，检查对齐、换行、字号、遮挡和图内标签；核对数据、公式、动画是否保留。删页后同步更新页脚总数、附件引用及案例序号。
5. **另存新版。** 不覆盖用户正在编辑的文件。处理中若用户再次保存，核对并合入相关最新修改；版本号与页数读取实际文件。
6. **工程注意。** 用 python-pptx 或原生 OOXML 修改 PPTX 时，坐标单位是 EMU：1 英寸 = 914400 EMU，9525 是 1 磅，两者不可混用。新增文本框若禁止换行，渲染后要逐项核对溢出，不能只看 XML。
